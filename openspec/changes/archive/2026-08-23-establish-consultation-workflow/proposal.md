## Why

当前政策问答仅返回明确标识的检索/占位回答，不会创建由政府办理的咨询工单。B1.6 需要为个人、企业和政府提供受权限保护、可追踪且可公开答复的真实咨询闭环；它只依赖已归档的 B1.1，可与外部真实 RAG 后端工作并行。

## What Changes

- 新增个人/企业“提交咨询”和“我的咨询”入口，以及政府“咨询办理”入口。
- 使用 B1.4 的已验证部门 map 作为可选政府部门目录；咨询表单触发分类并展示前三推荐与概率，但由用户最终选择。
- 新增部门 map 到专属政府组织/账号的受控映射，以及咨询、状态历史的数据库模型、版本化 API、角色/部门范围授权与不可跳过的状态机。
- 用户提交后自动分派至所选部门的专属政府账号；该账号回复后决定是否公开，只有其允许公开的脱敏答复进入既有公开历史问答。
- 在 B1.5 问答结果中增加明确标记的“转为人工咨询”辅助入口，预填可编辑草稿；问答提交动作不会自动创建工单。

## Capabilities

### New Capabilities

- `consultation-workflow`: 个人/企业提交咨询、政府办理、状态流转、公开答复与跨角色权限控制。

### Modified Capabilities

- `historical-qa`: 仅将已发布且脱敏的咨询答复作为公开历史问答来源展示。
- `policy-qa-entry`: 在政策问答结果中提供不会自动提交的人工咨询转换入口。

## Impact

- 新增 `backend/app/modules/consultation`、Alembic 迁移、受控演示 seed、`/api/v1/consultations` API 和 OpenAPI 合同。
- 更新历史问答读取边界、前端导航/路由/工单页面与政策问答结果卡片。
- 复用 B1.1 身份与组织权限；B1.4 分类仅可作为部门建议，真实 RAG、向量索引、模型供应商和 B1.5 API 合同不受影响。
- 对数据库迁移、演示数据和真实身份验证需要单独授权；不会读取或复用旧项目的咨询、Flask、RAG 或前端源码。
