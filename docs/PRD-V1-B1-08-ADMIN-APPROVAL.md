## 1. 页面定位

管理员审批页面是独立的后台功能，和公开注册流程分开设计、分开路由、分开验收；但与注册方案作为同一项 B18-007 一起开发。

新增管理员页面：

```text
/admin/registration-applications
/admin/registration-applications/{id}
```

只有已登录且后端确认拥有 `admin` 角色的用户可访问。个人、企业、政府账号访问页面或接口均返回现有 `ROLE_FORBIDDEN`。

## 2. 列表页

页面标题：注册申请管理。

展示内容：

- 待审核数量
- 申请类型筛选：企业、政府
- 状态筛选：待审核、已通过、已拒绝、已取消
- 关键词：申请编号、企业名称、统一社会信用代码、使用人姓名、部门名称
- 提交时间排序和分页

列表不得展示密码、密码哈希、完整手机号、完整邮箱或不必要的内部字段。

## 3. 详情页

企业申请详情展示：

- 企业名称、统一社会信用代码、企业类型、注册地址、所属地区
- 使用人姓名、职务、联系方式（按权限展示，必要时脱敏）
- 登录账号
- 提交时间、当前状态

政府申请详情展示：

- 选择的部门及目录中的部门名称
- 使用人姓名、职务、工作邮箱、联系电话
- 工号/内部识别信息（如有）
- 使用场景和申请理由
- 登录账号
- 提交时间、当前状态

详情页底部提供：

- 通过申请
- 拒绝申请
- 返回列表

已处理申请只读展示，不允许再次审批。

## 4. 审批接口

```http
GET  /api/v1/admin/registration-applications
GET  /api/v1/admin/registration-applications/{id}
POST /api/v1/admin/registration-applications/{id}/approve
POST /api/v1/admin/registration-applications/{id}/reject
```

所有接口统一执行：Bearer 登录验证 → identity 解析 → `admin` 角色校验 → 数据范围校验。

拒绝接口必须要求审核原因；通过接口可以填写可选备注。接口不得接受客户端传入最终角色、组织 ID、部门绑定或账号状态，这些值由服务端根据申请类型和目录关系生成。

## 5. 审批事务规则

### 企业通过

锁定申请并确认仍为 `pending` 后，在同一事务中：

1. 校验统一社会信用代码和登录账号唯一性；
2. 创建并激活企业组织；
3. 创建用户和 profile；
4. 绑定企业组织与 `enterprise` 角色；
5. 写入 `approved` 事件和审批人；
6. 提交事务。

任何一步失败都回滚，不留下半成品账号、组织或角色。

### 政府通过

锁定申请并确认仍为 `pending` 后，在同一事务中：

1. 重新校验部门仍在深圳目录且可用；
2. 确认该部门没有其他待审申请或有效政府账号；
3. 创建用户和 profile；
4. 绑定政府组织、`government` 角色和部门账号关系；
5. 写入 `approved` 事件和审批人；
6. 提交事务。

### 拒绝和并发

- 拒绝必须写入原因和 `rejected` 事件。
- 已通过、已拒绝或已取消的申请再次审批时返回 `REGISTRATION_ALREADY_PROCESSED`。
- 两名管理员同时操作时，行锁保证只有一个操作成功。
- 政府部门的“一个账号”限制通过唯一约束/锁定检查双重保证。

## 6. 页面交互和可访问性

- 通过/拒绝均使用二次确认弹窗。
- 拒绝弹窗必须填写原因，空原因不能提交。
- 审批进行中按钮禁用并显示明确状态。
- 成功后返回详情页并显示处理结果，列表计数同步更新。
- 失败时保留用户输入的审核意见，不泄露数据库或内部异常。
- 移动端列表支持横向滚动或卡片化，不允许操作按钮离开可视区域。
- 弹窗具备 `role="dialog"`、`aria-modal="true"`、标题/描述关联和焦点管理。

## 7. 管理员页面验收

- 非管理员无法访问页面和四个审批接口。
- 管理员可分页查看企业/政府申请并筛选状态。
- 企业通过后组织、账号、profile、角色同时生效。
- 政府通过后部门绑定正确，且同一部门不能创建第二个有效账号。
- 拒绝必须填写并保存原因。
- 重复点击、并发审批不会重复创建账号、组织或角色。
- 列表、详情和接口不泄露密码、哈希、完整联系方式或其他申请数据。
- 桌面和移动端页面无溢出、重叠和不可操作状态。

## 8. 与注册方案的开发关系

注册页、申请 API、审批 API、管理员页面和迁移作为同一项 B18-007 联合开发；但必须分别完成：

1. 注册/申请流程验收；
2. 管理员页面和权限验收；
3. 端到端“提交申请 → 管理员审批 → 账号登录”验收。

上述三部分已于 2026-09-05 在本机 standalone `aipolicy_local` 完成。管理员账号通过受控数据库写入创建；企业与政府申请均由管理员接口审批，审计事件、部门唯一绑定、重复审批冲突和四角色登录/工作区均回读通过。
