## 1. 目标与范围

B1.4 为深圳范围的政策/政务咨询文本提供一个可验证的部门分类基础闭环。系统只使用经资产审计、可复现加载的模型、tokenizer 和标签映射；分类结果由新的模块化服务返回，后续 B1.5 检索/RAG 可以复用该结果。模型推理不写业务表，不修改 Auth，不创建 Mock 分类结果。

本阶段包含：服务端模型资产 manifest 与只读加载、确定性输入规范化、深圳部门标签映射、鉴权分类 API、模型 readiness 与显式失败状态、基础前端分类工作区、测试和运行验收。模型文件可以位于项目配置指定的服务端路径；前端不接收路径或权重内容。

本阶段不包含：全文检索、embedding、RAG、聊天式回答、政策/问答关联、用户提交记录、AI run 持久化、模型训练、在线微调、跨地区 fallback、旧 Flask 路由或旧前端代码迁移。

## 2. 用户体验与权限

登录且拥有有效深圳应用身份的用户可以输入一段咨询文本并请求部门分类；四个现有角色沿用 B1.1 的身份和深圳范围校验。未登录、身份未配置、停用身份或非深圳身份使用既有 401/403/503 合同。文本为空、模型未就绪、资产不兼容和推理失败均显示明确的状态，不显示堆栈、文件路径、密钥或连接信息。

分类页面只展示输入文本、模型版本、返回的部门标签与置信度，以及明确的加载/失败/未就绪状态。页面不允许编辑模型、上传资产、执行导入或更改权限。

## 3. 结果合同

请求至少包含非空 `text`，地区由当前身份解析为稳定 `sz`。响应包含 `region_id`、`model_version` 和按置信度降序排列的一个或多个部门预测；每个预测包含稳定 `department_id`、显示名称和 `[0,1]` 范围内的有限 `confidence`。部门 ID 必须来自服务端已验证的 label binding，不能直接信任模型输出整数。

## 4. 验收标准

| ID | Given | When | Then |
|---|---|---|---|
| AC-B14-01 | 配置的模型、tokenizer、标签映射和部门 embeddings | readiness 检查执行 | 四项均经显式路径验证、格式兼容时返回安全 `ready` 与模型版本；任何缺失/不兼容均为 `not_ready` |
| AC-B14-02 | 有效深圳身份与非空文本 | 请求分类 API | 返回稳定的深圳结果、合法部门标签、有限置信度、模型版本和 `no-store` |
| AC-B14-03 | 未登录、非深圳、空文本或模型异常 | 请求分类 API | 使用既有错误信封返回 401/403/422/503 或稳定模型错误，不泄露路径、权重或堆栈 |
| AC-B14-04 | 同一输入和同一模型版本 | 重复请求 | 结果顺序和字段完全一致；服务端不写数据库 |
| AC-B14-05 | 运行验收执行 | 测试、Ruff、smoke、runtime、前端测试/build、strict validate | 全部通过；不执行迁移、Auth 写入、旧代码复用或 Mock fallback |

## 5. 数据与隐私

分类请求正文只在请求生命周期内处理，不默认记录原文，不把文本写入日志或 Supabase。日志仅记录安全的状态码、模型版本和请求 ID。服务端禁止向浏览器暴露模型资产路径、序列化权重、label 文件原文或环境配置。

## 6. 回滚与后续

回滚仅移除 B1.4 API、适配器、前端入口和配置，不执行数据库 downgrade 或删除。B1.5 如需要检索/RAG，必须重新建立 PRD/TECH/OpenSpec，明确分类结果与检索索引的接口和数据边界。
