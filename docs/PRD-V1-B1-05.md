## 1. 目标与范围

本阶段先建立用户可用的政策智能问答入口。个人服务与企业服务工作区进入后以问答窗口为主入口；首页也提供同一问答入口，使用户能够在提交问题前理解服务范围。界面沿用旧站可见的“政通惠”公共服务视觉语言：简洁的深圳地区上下文、清晰的输入框、提交动作和结果卡片。

后端建立稳定、鉴权的问答 API 及可替换的引擎边界。当前仅使用明确标识的占位引擎模拟问答状态流转，绝不把占位内容描述为真实检索、真实政策依据或模型回答。真实 RAG 的实现由后续指定开发者依照交接文档完成，并保持本阶段确定的 API、权限、错误与响应合同。

本阶段不创建向量索引、embedding、RAG 运行记录、会话历史或问答业务表；不执行迁移、数据写入、Auth 写入或模型/密钥配置；不实现流式响应、聊天多轮记忆、引用评价、后台管理或内容导入。

## 2. 用户体验与权限

已登录且具备有效深圳应用身份的个人或企业角色，可以输入一段问题并提交。输入提交后，页面显示处理中；当前占位引擎会返回带有“演示回答，尚未接入真实政策检索与生成”的结果卡片。真实 RAG 接入后，页面在不改变请求方式的前提下显示正式回答、来源列表和必要提示。

未登录用户可以看到首页问答入口，但提交时被引导登录，问题不会发送到后端。已登录但无个人或企业角色的用户不能使用问答 API。禁用、未配置或非深圳身份继续使用现有 401/403/503 合同。

## 3. 问答合同

请求包含非空 `question`；地区从当前身份固定解析为 `sz`，浏览器不能自行指定地区。响应包含安全的 `request_id`、`region_id`、`answer_mode`、`answer`、可选的 `sources[]` 和 `notices[]`。`answer_mode` 仅允许 `placeholder` 或未来的 `rag`；当前模式必须为 `placeholder`，并且 `sources` 为空。API 与页面不得返回输入原文、令牌、资产路径、模型配置、原始检索分数、内部异常或提示词。

## 4. 验收标准

| ID | Given | When | Then |
|---|---|---|---|
| AC-B15-01 | 首页、个人或企业服务入口 | 用户查看页面 | 可见一致的问答窗口、服务范围说明与无横向溢出的响应式布局 |
| AC-B15-02 | 有效深圳个人或企业身份 | 提交非空问题 | 前端调用真实鉴权 API，显示加载、明确 `placeholder` 演示回答和空来源状态 |
| AC-B15-03 | 未登录、无角色、越权、空问题或引擎错误 | 请求 API | 现有错误信封返回 401/403/422/503；请求原文与内部细节不泄露 |
| AC-B15-04 | 后续 RAG 开发者 | 阅读交接文档 | 能明确 API、身份边界、现有只读表、推荐扩展表、索引/摄取要求、替换边界、质量/安全验收和禁止事项 |
| AC-B15-05 | 运行验收 | 测试、Ruff、smoke、runtime、前端测试/build、strict validate | 全部通过；无迁移、数据库/Auth 写入、删除或静默 Mock/RAG fallback |

## 5. 数据、隐私与内容边界

问题只在当前请求生命周期内处理；当前阶段不记录问题、回答或会话。占位文本为静态产品提示，不引用、伪造或归因于政策文件。真实 RAG 上线前，必须确认其引用来源仅来自经批准的政策库/历史问答数据，建立数据版本、可追溯引用和敏感信息处理规则。

## 6. 后续与回滚

后续 RAG 开发者只能替换问答引擎实现，不能绕过 FastAPI 鉴权、地区范围、错误信封、`no-store` 或响应合同。若需要持久化运行、对话或索引，须先创建新的 TECH/OpenSpec 和获得迁移授权。回滚仅移除本阶段 API、入口页面和占位引擎，不执行数据库 downgrade 或数据删除。
